# TZ.md — техническое задание по этапам

Порядок строгий. Каждый этап: сделать → `npm run build` без ошибок → ручная проверка («ВОРОТА») → коммит конкретных файлов → коротко отчитаться пользователю и попросить подтвердить проверку. Только потом следующий этап.

Пользователь — не эксперт. Всё, что он должен сделать руками (аккаунты, env, клики в Vercel/BotFather), объясняй пронумерованными шагами простым языком.

---

## Этап 0 — Каркас и данные (≈20 мин)
1. `create-next-app` (TS, App Router, Tailwind, ESLint), установить: `leaflet react-leaflet leaflet-defaulticon-compatibility grammy @upstash/redis @vercel/blob @turf/boolean-point-in-polygon zod` + `@types/leaflet`.
2. `.gitignore` (`.env*`, кроме `.env.example`), `.env.example` со всеми переменными из CLAUDE.md.
3. `lib/types.ts` по схеме, `lib/redis.ts`, `lib/status.ts`:
   - цвета: clean `#16a34a`, check `#eab308`, detected `#dc2626`, in_progress `#dc2626` (штрих-пунктир), resolved `#16a34a` (бейдж), returned `#64748b`;
   - русские подписи; разрешённые переходы:
     `clean→check`; `check→clean` («сигнал не подтвердился») | `check→detected`; `detected→in_progress` | `detected→returned`; `in_progress→resolved` | `in_progress→returned`; `resolved→check` (новый сигнал).
4. `POST /api/seed` (заголовок `x-seed-secret` = `SEED_SECRET`): читает `data/seed.json`, очищает и заливает `parcels`, `apps`, `signals`.
5. `GET /api/state` → `{ parcels, signals, serverTime }`, `Cache-Control: no-store`.
6. Попроси пользователя: создать базу в Upstash (Redis → REST URL и TOKEN), вписать в `.env.local`.

ВОРОТА: `npm run dev` → `curl -X POST -H "x-seed-secret: ..." localhost:3000/api/seed` → `GET /api/state` возвращает 20 участков, 2 сигнала. Коммит.

## Этап 1 — Панель инспектора, P0 (≈45 мин)
Дизайн: светлый, «госпанель», спокойный. Шапка: «ЖерКөз · Панель земельного инспектора · г. Тараз» + плашка «Демо: тестовые данные».
Раскладка: слева сайдбар 360px, справа карта на всю высоту.

1. Карта (dynamic, ssr:false): центр по bounds всех участков; полигоны с заливкой по статусу (fillOpacity 0.45), обводка; hover — подсветка + tooltip «кадастровый № · статус»; клик — открыть карточку. Легенда цветов в углу карты. Атрибуция OSM.
2. Карточка участка (в сайдбаре): кадастровый номер, целевое назначение, площадь (га, 4 знака), адрес, бейдж статуса, тип нарушения (unused «Неиспользование» / seizure «Самозахват» / dump «Свалка»), контрольный срок + «осталось N дн.» / «просрочено на N дн.», история (лента), фото-галерея.
3. Действия: кнопки только разрешённых переходов (крупные, с подписями, напр. «Зафиксировать нарушение»). При переходе в `detected` — модалка: тип нарушения (обяз.), контрольный срок (date picker; по умолчанию +30 дней — это демо-значение, подписать «срок устанавливает инспектор»), комментарий. Каждое действие → запись в history.
4. Фото: кнопка «Добавить фото» → сжатие canvas → `POST /api/parcels/[id]/photos` (multipart; принимать только jpeg/png/webp ≤4 MB) → `put()` в Blob (public) → URL в `photos`. Просмотр — лайтбокс.
   Попроси пользователя: Vercel → Storage → Blob store (Public) → подключить к проекту → `vercel env pull` или вручную `BLOB_READ_WRITE_TOKEN`.
5. `PATCH /api/parcels/[id]`: zod-валидация, проверка перехода по `lib/status.ts`, иначе 409.
6. Polling `GET /api/state` каждые 4 с (пауза, когда вкладка скрыта). Выбранный участок не сбрасывается при обновлении.

ВОРОТА: сменил статус → цвет полигона сменился; F5 → сохранилось; загрузил фото → видно в карточке. Коммит.

## Этап 2 — Бот: ядро + ДЕПЛОЙ (≈40 мин)
1. `bot/bot.ts`: `new Bot(token)`; `app/api/telegram/route.ts`: `webhookCallback(bot, "std/http", { secretToken: process.env.TELEGRAM_WEBHOOK_SECRET })`.
2. `/start` → приветствие (2 строки: что умеет бот) + главное меню, reply-клавиатура (resize):
   `📄 Статус заявления` · `📚 Как оформить землю` · `📍 Сообщить о нарушении`.
3. Статус заявления: бот просит ввести трек-номер (пример KZ-2026-042) + inline-кнопка «Показать пример». Нормализация (trim, upper), regex `^KZ-\d{4}-\d{3}$`. Ответ:
   ```
   Заявление KZ-2026-024
   Процедура: Изменение целевого назначения
   ✅ Подано → ✅ На рассмотрении → 🔵 Выезд инспектора → ⚪ Решение
   Пояснение: <stageNote>
   Обновлено: 25.09.2026 14:40
   ```
   Для `rejected` — ❌ и пояснение обязательно. Не найден → «Заявление не найдено, проверьте номер» + кнопки «Ввести ещё раз» / «В меню».
4. База знаний: inline-кнопки 3 процедур → текст из `content/knowledge.ts` (разделы: Шаги, Документы, Сроки, Куда обращаться) + inline url-кнопки ссылок + «⬅ Назад». Пока контента нет — создай структуру:
   `{ id, title, steps: string[], documents: string[], timing: string, links: {title,url}[], checkedAt: string }` и заглушку: текст «Раздел наполняется. Актуальная информация — на портале egov.kz» + ссылка `https://egov.kz`. Контент пришлёт пользователь.
5. ДЕПЛОЙ: попроси пользователя: GitHub-репо (public) → Vercel Import → env-переменные → Deploy. Затем установить webhook:
   `curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<домен>/api/telegram&secret_token=<SECRET>"` и проверить `getWebhookInfo` (нет `last_error_message`). Засеять прод: POST `/api/seed`.

ВОРОТА (на проде, с телефона): /start → меню; KZ-2026-057 → отказ с пояснением; KZ-2026-999 → «не найдено»; все 3 кнопки базы знаний отвечают. Коммит.

## Этап 3 — «Народный контроль» + E2E, P0 (≈45 мин) — ГЛАВНЫЙ
Бот (конечный автомат в `bot:state:{chatId}`):
1. `📍 Сообщить о нарушении` → «Шаг 1 из 3: отправьте место» + reply-кнопка `📍 Отправить мою геопозицию` (`request_location`) + «Отмена». Принимать и location, отправленную вручную через скрепку.
2. Шаг 2 из 3: «Сфотографируйте нарушение». Берём `photo` с наибольшим размером (последний элемент массива). Если прислан документ-картинка — тоже принять (`document` с mime image/*).
3. Шаг 3 из 3: «Коротко опишите, что не так» + подсказки inline: «Заброшенный участок», «Свалка мусора», «Самозахват» (подставляют текст) — или свой текст (≤500 симв.).
4. Подтверждение: превью (адрес не нужен, «📍 точка получена») + «✅ Отправить» / «✖ Отмена».
5. Сохранить Signal (id `S-0001` через `INCR signal:seq`), `status: new`. `booleanPointInPolygon([lng,lat], parcel)` по всем участкам → `parcelId`. Если участок `clean` или `resolved` → перевести в `check` + history «Поступил сигнал S-xxxx от жителя».
6. Ответ жителю: «Сигнал S-0003 принят. Инспектор проверит его. Мы сообщим о результате здесь.» + главное меню. Неверный ввод на шаге → вежливая подсказка, шаг не сбрасывать.

Панель:
7. Сигналы — circleMarker радиус 9: new оранжевый `#f97316` с пульсацией (CSS), checking синий, confirmed красный, rejected серый, resolved зелёный. Слой сигналов поверх полигонов.
8. Сайдбар: вкладки «Участки» / «Сигналы (N новых)». Список сигналов: время, текст, статус; клик → карта flyTo + карточка сигнала.
9. Карточка сигнала: фото (`/api/tg-photo/[fileId]`; для seed-сигналов без фото — плейсхолдер «фото не приложено»), текст, время, привязанный участок (ссылка на карточку) или «вне зарегистрированных участков», действия: «Взять в проверку» (new→checking), «Подтвердить нарушение» (→confirmed), «Отклонить» (→rejected, причина обязательна), «Устранено» (confirmed→resolved). `PATCH /api/signals/[id]`.
10. «Подтвердить нарушение» при наличии `parcelId` → открыть ту же модалку, что в этапе 1, и перевести участок в `detected`.
11. `/api/tg-photo/[fileId]`: `bot.api.getFile` → fetch `https://api.telegram.org/file/bot<token>/<file_path>` → отдать поток с content-type, `Cache-Control: private, max-age=3000`. Валидировать fileId (`^[A-Za-z0-9_-]+$`).

ВОРОТА (прод, телефон + ноутбук): отправил гео+фото+текст → оранжевая точка на карте ≤5 с; участок под точкой стал жёлтым; фото открывается; «Подтвердить» → участок красный. Коммит.

## Этап 4 — P1: замыкание цикла и удобство (≈35 мин)
1. `lib/notify.ts`: при смене статуса сигнала → `bot.api.sendMessage(chatId, ...)` (для seed-сигналов с chatId 0 — пропустить):
   - checking: «🔎 Ваш сигнал S-xxxx взят в проверку инспектором.»
   - confirmed: «⚠️ По сигналу S-xxxx подтверждено нарушение. Нарушителю установлен срок устранения до ДД.ММ.ГГГГ.»
   - rejected: «Сигнал S-xxxx не подтвердился. Причина: … Спасибо за бдительность!»
   - resolved: «✅ Нарушение по сигналу S-xxxx устранено. Спасибо, что помогаете городу!»
   Ошибка отправки не должна ломать PATCH (логировать).
2. Просрочка: участки с дедлайном < сейчас и статусом detected/in_progress — обводка пунктиром + значок ⏰ в списке; счётчик «Просрочено: N».
3. Шапка — счётчики-плашки: Всего участков · Нарушения · На проверке · Новые сигналы · Просрочено. Клик по плашке = фильтр.
4. Фильтры в сайдбаре: чекбоксы статусов, поиск по кадастровому номеру.
5. Тост «Новый сигнал S-xxxx» + короткий звук при появлении нового сигнала (после первого polling).

ВОРОТА: сменил статус сигнала в панели → житель получил сообщение в Telegram ≤5 с; просроченные P-005 и P-017 подсвечены. Коммит.
